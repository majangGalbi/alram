# alram

디스코드 서버용 다기능 봇입니다. 지정한 시간에 사용자를 태그하는 **알림 예약**(단발·반복)을 중심으로
**버튼 투표**, **출석체크**, **뽑기 도구**, **서버 달력 일정표**를 제공합니다. 모든 시간은 한국 시간(Asia/Seoul) 기준입니다.

## 알림 예약 (`/예약`)

`/예약 일시:<시간> 멘션:<사용자> 메시지:<내용>` 으로 지정한 시간에 대상 사용자를 태그해 메시지를 보냅니다.
예약 확인 메시지는 아무도 핑하지 않고(멘션은 표시만), 실제 알림 때만 대상 사용자 한 명을 핑합니다.

### `/예약` 의 `일시` 입력 형식

시간 해석은 [`time_parser.py`](time_parser.py)가 맡습니다. 모든 시간은 **한국 시간(Asia/Seoul)** 기준입니다.
띄어쓰기는 자유롭게 해도 되고(`내일오후3시` = `내일 오후 3시`), 전각 문자(`１５：３０`)도 됩니다.
끝에 붙는 `에`, `쯤`, `정각`, `까지`도 인식합니다.

아래 예시는 **2026-11-05(목) 14:00에 입력했다고 가정**한 결과입니다.

#### 상대 시간

| 입력 | 결과 |
| --- | --- |
| `30분 뒤`, `30분 후에`, `30분 있다가`, `30분 이따가` | 오늘 14:30 |
| `1시간 30분 후`, `1시간 반 뒤`, `한시간 반 뒤`, `1.5시간 뒤` | 오늘 15:30 |
| `삼십분 뒤`, `십오분 후`, `반시간 뒤` | 14:30 / 14:15 / 14:30 |
| `10초 뒤`, `1분 30초 뒤` | 14:00:10 / 14:01:30 |
| `2일 뒤`, `이틀 뒤`, `사흘 후`, `일주일 뒤`, `2주 후` | 그 날짜의 같은 시각 |
| `3일 뒤 오후 2시`, `이틀 뒤 오전 9시 30분` | 해당 날짜의 그 시각 |
| `in 10 minutes`, `in 1h30m`, `in an hour`, `in half an hour` | 영어 상대 시간 |
| `10 minutes later`, `2 hours from now`, `after 15 minutes` | 영어 상대 시간 |

#### 날짜 + 시각

| 입력 | 결과 |
| --- | --- |
| `내일 오후 3시`, `낼 오후 3시`, `내일 15:30`, `내일 오후 3시 반` | 11-06 15:00 / 15:30 |
| `모레 아침 7시 반`, `내일모레 오후 5시`, `글피 오후 1시` | 11-07 07:30 / 11-07 17:00 / 11-08 13:00 |
| `오늘 저녁 7시`, `오늘 밤 11시`, `오늘 밤 12시` | 19:00 / 23:00 / 11-06 00:00 |
| `다음주 월요일 9시`, `담주 월요일 9시`, `다다음주 월요일 10시` | 11-09 09:00 / 11-09 09:00 / 11-16 10:00 |
| `이번주 토요일 오후 3시`, `금요일 저녁 7시`, `금욜 저녁 7시` | 11-07 15:00 / 11-06 19:00 |
| `2026년 6월 2일 8시 10분`, `2026년 5월 23일 오후 1시 30분 0초` | 해당 일시 |
| `2026-12-25 18:00`, `2026.12.25 18:00`, `2026/12/25 18:00` | 12-25 18:00 |
| `12월 25일 오후 6시`, `12/25 6pm`, `십이월 이십오일 오후 여섯시` | 12-25 18:00 |
| `20일 오후 3시`, `다음달 3일 오후 3시`, `이번달 20일 오후 3시` | 이번 달 / 다음 달 해당 일 |
| `11월 6일 금요일 9시` | 요일이 날짜와 맞는지 확인 후 11-06 09:00 |

#### 시각만

| 입력 | 결과 |
| --- | --- |
| `15:30`, `1530`, `오후 3시 30분`, `3:30pm`, `3:30 PM` | 오늘 15:30 |
| `0730`, `07:30` (0으로 시작 = 24시간제) | 내일 07:30 (오늘은 지났으므로) |
| `7시30분`, `7시30`, `7:30` | 19:30 (07:30은 지났으므로 가장 가까운 미래) |
| `세시 이십분`, `다섯시 십분`, `열한시 오십구분` | 15:20 / 17:10 / 23:59 |
| `오후 열두시`, `정오`, `noon`, `12:00` | 다음 12:00 |
| `자정`, `midnight`, `밤 12시`, `24시` | 다가오는 00:00 |
| `새벽 3시`, `밤 3시` | 내일 03:00 |

#### 영어

`tomorrow 7am`, `7am tomorrow`, `tmr 9am`, `tomorrow at 7:30 pm`, `today 5pm`, `tonight 9pm`,
`day after tomorrow 10am`, `next monday 9am`, `friday 6pm`, `noon tomorrow`

#### 해석 규칙

- **날짜 없이 시각만** 입력하면 **가장 가까운 미래**로 잡습니다.
  오전/오후가 없으면 `3시`는 03:00과 15:00 중 먼저 오는 시각, 이미 지났으면 다음 날입니다.
- **날짜를 지정했고 오전/오후가 없으면** 1~6시는 오후, 7~12시는 오전/정오로 봅니다.
  (`내일 3시` → 15:00, `내일 7시` → 07:00. 새벽 시간은 `새벽 3시`, `내일 03:00`처럼 써 주세요.)
- `오늘 …`, `이번주 …`, `2026년 …`처럼 **날짜를 명시했는데 이미 지난 시각**이면 넘기지 않고
  "현재 시간보다 이전 시간은 예약할 수 없습니다" 안내가 나옵니다.
- 연도 없는 `M월 D일`이 이미 지났으면 내년, `D일`이 지났으면 다음 달로 잡습니다.
- 요일만 쓰면 다가오는 그 요일입니다(오늘이 그 요일이고 시각이 지났으면 다음 주).
  `다음주 X요일`은 다음 주(월요일 시작)의 X요일입니다. `next X`도 같습니다.
- `내일 자정`은 내일 밤 12시, 즉 **모레 00:00**입니다.
- `오전/새벽/아침`은 0~12시, `오후`는 12~23시, `낮`/`점심`은 그 시간대에 맞춰 계산하고,
  `저녁`은 오후, `밤 1~5시`는 다음 날 새벽으로 계산합니다.

#### 거부되는 입력 (사유를 함께 안내)

| 입력 | 이유 |
| --- | --- |
| `내일 3시 회의`, `5분 후 알림` | 해석할 수 없는 글자가 섞여 있음 (추측하지 않음) |
| `내일`, `다음주 월요일`, `오후`, `30분` | 시각이나 단위가 빠짐 |
| `25시`, `오후 15시`, `3시 60분`, `2월 30일 3시` | 범위를 벗어나거나 존재하지 않는 날짜 |
| `3시 30분 뒤`, `내일 30분 뒤` | 상대 시간과 시각/날짜를 동시에 씀 (모호함) |
| `11월 6일 토요일 9시`, `내일 월요일 3시` | 날짜와 요일이 맞지 않음 |
| `730`, `3 30`, `3:3` | 형식이 모호함 |

### 반복 예약 (🔁)

`/예약`의 `일시`에 반복 표현을 쓰면 **반복 알림**으로 등록됩니다(한국 시간 기준).
해석은 `time_parser.parse_recurrence()`가 맡고, 봇은 APScheduler `CronTrigger`/`IntervalTrigger`로 등록합니다.

```
/예약 일시:매일 오전 7시 멘션:@홍길동 메시지:기상!
/예약 일시:매주 월수금 오후 6시 멘션:@홍길동 메시지:운동 갈 시간
/예약 일시:2시간마다 멘션:@홍길동 메시지:스트레칭
```

| 입력 | 반복 규칙 |
| --- | --- |
| `매일 오전 6시`, `매일 아침 7시 30분`, `날마다 오후 10시`, `하루마다 8시`, `매일 7:30` | 매일 그 시각 |
| `평일 8시`, `평일마다 오전 8시 30분`, `매주 평일 9시`, `주중 9시` | 월~금 |
| `주말 오전 10시`, `주말마다 11시` | 토·일 |
| `매주 월요일 9시`, `월요일마다 오후 6시`, `매주 월욜 9시` | 매주 그 요일 |
| `매주 월수금 7시`, `매주 월, 수, 금 7시`, `매주 월/수/금 7시`, `매주 월요일과 목요일 9시` | 여러 요일 |
| `매주 월~금 9시`, `매주 월요일부터 금요일까지 9시`, `매주 금~월 9시` | 요일 범위 (주를 넘어가도 됨) |
| `매월 1일 오전 9시`, `매달 15일 오후 3시`, `매월 말일 오후 6시` | 매월 그 날 (`31일`처럼 없는 달은 건너뜀) |
| `매년 12월 25일 오전 9시`, `해마다 5월 5일 10시` | 매년 그 날 (`2월 29일`은 윤년에만) |
| `매시간`, `매시 정각`, `매시 30분` | 매시 정각 / 매시 30분 |
| `30분마다`, `2시간마다`, `1시간 30분마다`, `두시간마다`, `2시간 간격으로` | 등록 시각부터 그 간격마다 (최소 10분, 최대 7일) |
| `every day 7am`, `daily 7am`, `every weekday 8am`, `weekends 10am` | 영어: 매일 / 평일 / 주말 |
| `every monday 9am`, `every mon, wed, fri 9am`, `every mon-fri 8am` | 영어: 요일 |
| `every month on the 15th 9am`, `every 30 minutes`, `every 2 hours`, `every hour`, `hourly` | 영어: 매월 / 간격 / 매시간 |

- 시각 해석 규칙은 1회성 예약과 같습니다. 오전/오후가 없으면 1~6시는 오후, 7~12시는 오전입니다
  (`매일 3시` → 오후 3시). 확인 메시지에 해석된 규칙(`🔁 반복: 매일 오후 3시`)이 표시되니 꼭 확인하세요.
- `매주 금요일 밤 12시`/`자정`, `매주 월요일 밤 1시`처럼 날짜가 넘어가는 시각은 다음 요일로 계산됩니다
  (각각 토요일 0시, 화요일 1시).
- `/예약목록`에 반복 규칙과 **다음 알림** 시각이 표시되고, `/예약취소 <번호>`로 반복 예약을 끝낼 수 있습니다.
- 반복 예약은 서버(DM은 채널)당 최대 25개까지 등록할 수 있습니다.

거부되는 반복 입력: `5분마다`(10분 미만), `3일마다`·`2주마다`(일/주 단위 간격 — `매일`, `매주 X요일` 사용),
`매주 9시`(요일 없음), `매월 9시`(날짜 없음), `매일`(시각 없음), `30분마다 9시`(간격과 시각 동시 사용),
`매월 말일 자정`(날짜가 넘어가 모호), `매일 3시 회의`(해석할 수 없는 글자)

### 예약 저장 (재시작 후에도 유지)

예약은 SQLite 파일에 저장되어 봇을 재시작·재배포해도 유지됩니다
(APScheduler `SQLAlchemyJobStore`, 시작 시 `⏰ 스케줄러가 시작되었습니다. (저장된 예약 N건)` 로그).

| 환경변수 | 설명 | 기본값 |
| --- | --- | --- |
| `JOBS_DB_PATH` | SQLite 파일 경로 (상위 폴더가 없으면 자동 생성) | `bot.py` 옆의 `jobs.sqlite` |
| `JOBS_DB_URL` | SQLAlchemy DB URL. 설정하면 `JOBS_DB_PATH`보다 우선 | (없음) |

- **봇이 꺼져 있는 동안 지나간 예약**: 예정 시각에서 5분(`MISFIRE_GRACE_SECONDS`) 이내에 다시 켜지면
  시작 직후 **한 번** 전송합니다. 5분이 넘었으면 전송하지 않고 삭제하며 로그
  (`⚠️ 예약 … 지연 허용 시간을 넘겨 전송되지 않았습니다`)를 남깁니다.
- **호스팅 주의**: Heroku처럼 재시작·재배포 때 로컬 파일이 초기화되는 환경에서는 SQLite 파일도 사라집니다.
  영구 디스크가 있으면 `JOBS_DB_PATH`를 그 경로로 지정하고, 없으면 `JOBS_DB_URL`로 외부 DB를 지정하세요.
  (PostgreSQL 등은 해당 드라이버를 따로 설치해야 하며, SQLAlchemy 1.4 이상은 `postgres://`가 아닌
  `postgresql://` 형식만 받습니다. 외부 DB 연동은 테스트하지 않았습니다.)
- 예약 작업은 DB에 `"bot:send_ping"` 함수 참조와 기본 타입 인자로 저장됩니다.
  `send_ping`의 이름·위치·인자 이름을 바꾸면 이미 저장된 예약을 복원하지 못하니 주의하세요.

### 응답 공개 범위

- `/예약`: 입력이 잘못되면(시간 해석 실패·과거 시각·메시지 길이 초과) **본인에게만** 오류가 보이고,
  예약에 성공하면 채널의 모두에게 확인 메시지가 보입니다.
- `/예약목록`: 예약이 없으면 본인에게만 안내, 있으면 현재 서버의 예약을 공개로 표시합니다.
- `/예약취소`: 성공은 공개, 번호를 찾지 못하면 본인에게만 안내합니다.

## 버튼 투표 (/투표, /투표마감)

```
/투표 질문:점심 뭐 먹지? 항목:짜장, 짬뽕, 볶음밥 마감:오후 1시 중복허용:False 익명:True
```

| 옵션 | 설명 |
| --- | --- |
| `질문` | 투표 질문 (최대 200자) |
| `항목` | 쉼표(`,`)로 구분한 2~10개 항목. 항목당 최대 80자(디스코드 버튼 라벨 제한), 중복 불가 |
| `마감` | (선택) 자동 마감 시각. `/예약`과 같은 형식(`30분 뒤`, `오후 6시`, `내일 오전 9시` 등), 최대 30일 이내 |
| `중복허용` | (기본 `False`) `True`면 여러 항목에 투표 가능 |
| `익명` | (기본 `True`) `False`면 항목별 투표자를 임베드에 표시 |

- 항목 버튼을 누르면 투표, 다른 버튼을 누르면 변경(중복허용 시 추가), **같은 버튼을 다시 누르면 취소**됩니다.
  결과 안내는 누른 사람에게만 보입니다.
- 임베드의 막대 그래프·득표수·퍼센트(참여 인원 대비)가 실시간으로 갱신됩니다.
- 마감 시각이 되면 버튼이 비활성화되고 결과가 발표됩니다. 동점이면 동점 항목을 모두 발표합니다.
- `/투표마감 메시지id:<투표 메시지 ID>` : 투표를 만든 사람 또는 서버 관리자(관리자/서버 관리 권한)가 수동 마감.
  메시지 ID는 개발자 모드에서 메시지 우클릭 → "메시지 ID 복사". (디스코드 옵션 이름은 소문자만 허용되어 `메시지id`)
- 서버 채널에서만 사용 가능하며, 다른 서버의 투표는 조회·마감할 수 없습니다. 서버당 진행 중 투표는 최대 50개.
- 질문/항목에 `@everyone`, 역할 멘션을 넣어도 알림이 울리지 않습니다.
- 투표 데이터는 SQLite 파일에 저장되어 **봇을 재시작해도 진행 중인 투표의 버튼과 자동 마감이 유지**됩니다.
  저장 경로는 환경변수 `POLLS_DB_PATH`(기본 `bot.py` 옆의 `polls.db`). Heroku 등 파일 시스템이 휘발성인 호스팅에서는
  영구 디스크 경로를 지정해야 재배포 후에도 유지됩니다.

## 출석체크 (`/출석`, `/출석현황`, `/랭킹`)

| 명령 | 설명 |
|---|---|
| `/출석` | 하루 1회 출석. **한국시간(Asia/Seoul) 자정** 기준으로 날짜가 바뀝니다. 서버별·사용자별로 따로 집계합니다. 이미 출석했다면 본인에게만 안내가 보입니다. |
| `/출석현황 [사용자]` | 누적 출석·연속 출석·최장 연속·포인트·오늘 출석 여부와 이번 달 출석 달력(텍스트, 출석일은 ✅). 사용자를 비우면 본인. |
| `/랭킹 [기준]` | 서버 상위 10명. 기준은 `포인트`(기본) / `연속` / `누적`. |

포인트 규칙 (`attendance.py` 상단 상수로 조정 가능):

- 기본 **10P**
- 연속 보너스: 연속 2일째부터 하루당 **+2P**, 최대 **+20P** (연속 11일째부터 상한)
- 연속 **7일마다** (7·14·21일…) **+50P** 추가
- 예) 1일째 10P, 2일째 12P, 7일째 10+12+50 = 72P

연속 출석은 어제 출석했으면 이어지고, 하루라도 빠지면 다음 출석 때 1일부터 다시 시작합니다.
`/출석현황`·`/랭킹(연속)` 에서는 어제까지 출석이 이어진 경우만 연속으로 표시하고, 끊긴 기록은 0일로 보여줍니다(최장 연속은 유지).

데이터는 SQLite 파일에 저장됩니다. 경로는 환경변수 `ATTENDANCE_DB_PATH` 로 지정하며 기본값은 `bot.py` 옆의 `attendance.db` 입니다(첫 사용 시 생성).
`(서버, 사용자, 날짜)` UNIQUE 제약과 `BEGIN IMMEDIATE` 트랜잭션으로 같은 날 중복 출석·동시 요청 중복 지급을 막습니다.
Heroku 처럼 파일시스템이 재시작 때 초기화되는 호스팅에서는 영구 디스크 경로를 `ATTENDANCE_DB_PATH` 로 지정해야 기록이 유지됩니다.

## 뽑기 도구 (`/주사위`, `/뽑기`, `/팀나누기`)

| 명령 | 설명 |
|---|---|
| `/주사위 [표현식]` | `NdM+K` 형식. 기본 `1d6`. 예: `2d6+3`, `d20`, `3d8-1`. 개수 1~100, 면 2~1000, 보정값 ±100000, 30자 이하. |
| `/뽑기 항목:"a, b, c" [개수]` | 쉼표(또는 줄바꿈)로 구분한 항목 중 무작위로 `개수`(기본 1)만큼 중복 없이 뽑습니다. 빈 항목·중복 항목은 제거. 입력 1000자·항목 100개·항목당 100자 이하. |
| `/팀나누기 [팀수]` | 호출한 사람이 들어가 있는 **음성 채널** 멤버(봇 제외)를 무작위로 섞어 `팀수`(기본 2, 2~10)개 팀으로 나눕니다. 팀 인원 차이는 최대 1명. 음성 채널에 없으면 본인에게만 안내합니다. |

난수는 `random.SystemRandom`(운영체제 난수원, `secrets` 모듈과 같은 소스)을 사용합니다.
사용자가 입력한 텍스트에 `@everyone`·`@here`·역할 멘션이 있어도 알림이 가지 않도록 `AllowedMentions.none()` 으로 보냅니다(팀나누기 결과의 멤버 멘션도 알림 없이 표시만 됨). 입력 오류는 본인에게만 보입니다.

### 필요한 인텐트 / 디스코드 개발자 포털 설정

- `/팀나누기` 는 음성 채널 참가자를 봇의 캐시에서 읽으므로 **`voice_states` 인텐트**가 필요합니다. `discord.Intents.default()` 에 이미 포함되어 있고 특권(Privileged) 인텐트가 아니므로 **포털에서 따로 켤 것은 없습니다.** (꺼져 있으면 봇 시작 시 경고를 출력합니다.)
- 봇은 기존 기능 때문에 `message_content` 인텐트를 사용합니다. 이 인텐트는 특권 인텐트이므로 [Discord Developer Portal](https://discord.com/developers/applications) → 애플리케이션 선택 → **Bot** → **Privileged Gateway Intents** 에서 **MESSAGE CONTENT INTENT** 가 켜져 있어야 합니다.
- **SERVER MEMBERS INTENT** 는 이 기능들에 필요하지 않습니다. 다만 `/랭킹` 에서 봇 캐시에 없는 멤버는 이름 대신 `<@아이디>` 멘션 형태(알림 없음)로 표시됩니다.

## 채팅 레벨·경험치 (`/레벨`, `/레벨랭킹`, `/레벨설정`, `/레벨보상`)

서버 채널에 메시지를 보내면 경험치(XP)가 쌓이고 레벨이 오릅니다 (`leveling.py`).

| 명령 | 설명 |
|---|---|
| `/레벨 [사용자]` | 레벨·누적 XP·다음 레벨까지 진행 막대·서버 내 순위. Pillow 와 저장소의 `fonts/NanumGothic-*.ttf` 로 랭크 카드 PNG 를 그리고, 그릴 수 없으면 임베드로 보여줍니다. 사용자를 비우면 본인. |
| `/레벨랭킹` | 서버 XP 상위 10명 (동점이면 사용자 ID 순). 멘션은 알림 없이 표시만 됩니다. |
| `/레벨설정 레벨업알림:<켜기\|끄기> [채널]` | 레벨업 축하 메시지 켜기/끄기. 채널을 지정하면 그 채널로, 비우면 메시지를 보낸 채널로 보냅니다. **서버 관리(Manage Server) 권한** 필요. |
| `/레벨보상 레벨 역할` | 해당 레벨에 도달하면 역할을 자동 지급. 같은 레벨에 다시 등록하면 덮어씁니다(서버당 최대 50개). **서버 관리 권한** 필요. |

XP 규칙 (`leveling.py` 상단 상수로 조정 가능):

- 서버 메시지 1건당 **15~25 XP** 무작위, 같은 사용자는 **60초 쿨다운**(쿨다운 중 메시지는 XP 없음). 봇·웹훅·DM 메시지는 제외.
- 레벨 L → L+1 에 필요한 XP = `5*L^2 + 50*L + 100` (누적). 예) 레벨 1 = 누적 100, 레벨 2 = 255, 레벨 3 = 475.
- 레벨업 시 알림 메시지는 해당 사용자만 멘션합니다(`@everyone`·역할 멘션은 울리지 않음). 명령 오류·권한 안내는 본인에게만 보입니다.
- 보상 역할은 레벨업 순간에 지급하며, 그 레벨 이하에 등록된 보상 중 아직 없는 역할도 함께 지급합니다.
  봇의 가장 높은 역할보다 같거나 높은 역할, `@everyone`, 연동(관리형) 역할은 `/레벨보상` 에서 거부하고 이유를 안내합니다.
  등록 후 역할 위치가 바뀌어 지급할 수 없게 되면 지급을 건너뜁니다.

데이터는 SQLite 파일에 서버별로 분리 저장됩니다. 경로는 환경변수 `LEVELING_DB_PATH`, 기본값은 실행 위치의 `leveling.db` 입니다(첫 사용 시 생성).
DB 작업은 짧은 트랜잭션으로 `asyncio.to_thread` 에서 실행해 이벤트 루프를 막지 않으며, 쿨다운 확인과 XP 적립은 `BEGIN IMMEDIATE` 트랜잭션 하나로 처리합니다.

### 필요한 인텐트 / 봇 권한

- 메시지 **내용은 읽지 않습니다.** 작성자·서버·채널 정보만 쓰므로 레벨 기능 자체는 `message_content` 인텐트가 필요 없고, `discord.Intents.default()` 에 포함된 `guild_messages` 인텐트만으로 동작합니다(특권 인텐트 아님). SERVER MEMBERS INTENT 도 필요 없습니다.
- 레벨업 알림: 알림 채널의 **채널 보기**·**메시지 보내기** 권한. 권한이 없으면 알림을 건너뜁니다.
- 보상 역할: 봇에게 **역할 관리(Manage Roles)** 권한이 있어야 하고, 지급할 역할이 봇의 가장 높은 역할보다 **아래**에 있어야 합니다(서버 설정 → 역할에서 봇 역할을 위로 이동).
- `on_message` 는 `bot.add_listener` 로 등록하므로 다른 기능의 이벤트 처리와 충돌하지 않습니다.

## 서버 달력 일정표 (`schedule_calendar.py`)

서버(길드)마다 따로 관리되는 일정표입니다. 모든 시간은 한국 시간(Asia/Seoul) 기준이며, DM 에서는 사용할 수 없습니다.

| 명령 | 설명 |
|---|---|
| `/일정추가 제목 일시 [종료] [설명] [종일] [알림분]` | 일정 추가. `일시`·`종료`는 `/예약`과 같은 형식(`내일 오후 3시`, `다음주 금요일 7시`, `12월 24일 18:30` …) |
| `/일정목록 [기간]` | `오늘` / `이번주`(기본, 일~토) / `이번달` / `다음달` 일정을 날짜별로 묶어 표시 |
| `/달력 [년] [월] [이미지]` | 실제 달력 모양의 월간 격자 PNG(일~토 7열, 각 날짜 칸 안에 `시각 제목`, 넘치면 `+N개`, 오늘 강조, 일·토 색 구분) + 그 달 일정 요약. `◀ 이전 달` / `오늘` / `다음 달 ▶` 버튼으로 넘길 수 있음. `이미지:False` 면 텍스트 달력(`[ 5]` 오늘, `*` 일정 있는 날) |
| `/일정수정 번호 [제목] [일시] [종료] [설명] [종일] [알림분]` | 입력한 항목만 수정. `종료`·`설명`에 `없음`을 넣으면 지움 |
| `/일정삭제 번호` | 일정 삭제 |
| `/일정일괄추가 [파일]` | 여러 일정을 한 번에 등록. `.txt`/`.csv` 첨부(최대 512KB), 파일 없이 실행하면 여러 줄 입력창(4000자)이 열림 |
| `/일정내보내기 [기간]` | `오늘`/`이번주`/`이번달`(기본)/`다음달`/`전체` 일정을 일괄 등록과 같은 형식의 `.txt` 로 내보냄 |

- **번호**: `/일정목록`·`/달력`에 표시되는 `#번호`.
- **종일 일정**: `종일:True` 로 하면 `일시`에 날짜만 입력합니다(`내일`, `12월 25일`, `2026-12-25`, `다음주 금요일`). 시각을 함께 쓰면 거부됩니다.
- **종료 일시**: 날짜가 들어 있으면(`모레 오전 10시`) 그대로, 시각·기간만 쓰면(`오후 5시`, `2시간 뒤`) 시작 일시 기준으로 해석합니다.
- **알림**: 시작 `알림분`(기본 10분) 전에 일정을 만든 채널로 알림을 보냅니다. `0`은 시작 시각, `-1`은 알림 없음. 종일 일정은 당일 오전 9시 기준입니다. 봇이 1분마다 확인하므로 최대 1분 정도 늦을 수 있고, 봇이 꺼져 있다가 10분 넘게 지난 알림은 보내지 않습니다. 발송 여부는 DB 에 기록되어 재시작해도 중복 발송되지 않으며, 일시·알림분을 수정하면 다시 알림 대상이 됩니다.
- **권한**: 수정·삭제는 일정을 만든 사람 또는 `서버 관리`(또는 관리자) 권한이 있는 사람만 할 수 있습니다.
- **멘션 차단**: 제목·설명에 `@everyone`, 역할 멘션 등을 넣어도 알림이 울리지 않습니다. 오류 메시지는 본인에게만 보입니다.
- **이미지 달력(기본)**: Pillow 로 그립니다. 한글 폰트는 저장소의 `fonts/NanumGothic-Regular.ttf`·`NanumGothic-Bold.ttf`(SIL Open Font License 1.1, `fonts/OFL.txt`)를 우선 사용하고, 없으면 `CALENDAR_FONT_PATH` → 시스템 폰트(Noto Sans CJK·WenQuanYi 등) 순으로 찾습니다. 모두 실패하면 텍스트 달력으로 대신 보여주고 그 사실을 안내합니다.

### 일괄 등록 형식

한 줄에 일정 하나: `날짜 [시각] | 제목 | 설명(선택) | 알림N분전(선택)`

```text
# '#' 으로 시작하는 줄과 빈 줄은 무시
2026-11-20 14:00 | 팀 회의 | 3층 회의실 | 30
2026-11-25 | 창립기념일          ← 시각이 없으면 종일 일정
11/27 19:30 | 회식              ← 연도를 생략하면 가장 가까운 미래
11월 28일 오후 2시 | 워크숍      ← 한국어 날짜·시각도 가능
2026-12-31 | 종무식 | | -1      ← 알림 -1 = 알림 없음 (비우면 10분 전)
```

- 날짜: `2026-11-20`, `2026/11/20`, `2026.11.20`, `11/20`, `11-20`, `11월 20일`, `2026년 12월 3일`. 존재하지 않는 날짜(`11월 32일`, `2027년 2월 29일`)는 오류 줄로 표시됩니다.
- 시각: `14:00`, `14시`, `오후 2시`, `오전 9시 30분`, `오후 2시 반`, `오후 2:15`. `오전`/`오후` 가 없으면 24시간제(`3시` = 새벽 3시)입니다.
- 알림: `30`, `30분전`, `알림30분전` 모두 허용. 범위 -1 ~ 10080.
- CSV 도 허용: 첫 줄 헤더가 `날짜,시각,제목,설명,알림`.
- 인코딩: UTF-8, UTF-8(BOM), CP949(EUC-KR) 자동 인식.
- 한 번에 최대 1000줄. 먼저 전체를 검사해 **본인에게만** 미리보기(등록 가능 건수, 오류 줄 번호와 사유, 앞부분 샘플)와 [등록]/[취소] 버튼을 보여주고, [등록]을 누르면 하나의 트랜잭션으로 저장합니다. 오류 줄은 제외되고, 같은 제목+같은 일시의 기존 일정(또는 파일 안 중복)은 건너뛴 뒤 개수를 알려 줍니다.
- `/일정내보내기` 파일을 그대로 `/일정일괄추가` 에 올리면 다시 등록됩니다. 단 종료 일시는 형식에 없어 내보내지 않으며, 제목·설명 안의 `|` 는 `｜`(전각), 줄바꿈은 공백으로 바뀝니다.
- 예시: [`examples/일정_예시.txt`](examples/일정_예시.txt)

환경변수:

| 이름 | 기본값 | 설명 |
|---|---|---|
| `CALENDAR_DB_PATH` | `bot.py` 옆의 `calendar.db` | 일정 SQLite 파일 경로 |
| `CALENDAR_FONT_PATH` | (저장소 나눔고딕 다음 순위) | 이미지 달력에 쓸 한글 TTF/TTC/OTF 폰트 |

## 데이터 저장 위치

모든 데이터는 SQLite 파일에 저장되며, 기본값은 실행 위치와 관계없이 **`bot.py` 와 같은 폴더**입니다.
파일은 첫 사용 시 자동으로 만들어지고 `.gitignore`·`.dockerignore` 에 포함되어 커밋/이미지에 들어가지 않습니다.

| 기능 | 파일 | 경로 환경변수 |
| --- | --- | --- |
| 알림 예약 | `jobs.sqlite` | `JOBS_DB_PATH` (또는 SQLAlchemy URL `JOBS_DB_URL`) |
| 투표 | `polls.db` | `POLLS_DB_PATH` |
| 출석체크 | `attendance.db` | `ATTENDANCE_DB_PATH` |
| 일정표 | `calendar.db` | `CALENDAR_DB_PATH` |

Heroku 처럼 재시작 때 파일 시스템이 초기화되는 호스팅에서는 위 경로를 영구 디스크로 지정해야 데이터가 유지됩니다.

## 디스코드 인텐트 설정


- `/팀나누기` 는 음성 채널 참가자를 봇의 캐시에서 읽으므로 **`voice_states` 인텐트**가 필요합니다. `discord.Intents.default()` 에 이미 포함되어 있고 특권(Privileged) 인텐트가 아니므로 **포털에서 따로 켤 것은 없습니다.** (꺼져 있으면 봇 시작 시 경고를 출력합니다.)
- 봇은 기존 기능 때문에 `message_content` 인텐트를 사용합니다. 이 인텐트는 특권 인텐트이므로 [Discord Developer Portal](https://discord.com/developers/applications) → 애플리케이션 선택 → **Bot** → **Privileged Gateway Intents** 에서 **MESSAGE CONTENT INTENT** 가 켜져 있어야 합니다.
- **SERVER MEMBERS INTENT** 는 이 기능들에 필요하지 않습니다. 다만 `/랭킹` 에서 봇 캐시에 없는 멤버는 이름 대신 `<@아이디>` 멘션 형태(알림 없음)로 표시됩니다.

## 도움말 (`/도움말`, 웹 `/help`)

- `/도움말 [카테고리]`: 카테고리별 명령 설명·파라미터·예시를 임베드로 보여주고, 드롭다운으로 카테고리를 전환합니다. **본인에게만** 보입니다.
  `카테고리` 에는 카테고리 이름(예: `투표`) 또는 명령 이름(예: `주사위`)을 넣을 수 있고, 비우면 전체 목록입니다.
- 명령 목록은 `bot.tree.get_commands()` 에서 이름·설명·파라미터를 읽어 **자동 생성**합니다(`help.py`).
  카테고리와 예시만 `help.py` 의 `COMMAND_CATEGORIES` / `COMMAND_EXAMPLES` 로 보강하며, 여기에 없는 새 명령은 자동으로 **기타** 로 분류됩니다.
- keep-alive 웹서버의 `/help` (또는 `/commands`) 경로에서 같은 목록을 HTML 페이지(모바일·다크모드 대응, 카테고리 목차)로 볼 수 있습니다.
  페이지에는 명령 설명과 초대 안내만 들어가며 서버·사용자 데이터는 포함하지 않습니다. `/` 응답은 그대로입니다.

### 봇 초대 링크 만들기

`CLIENT_ID` 를 [Discord Developer Portal](https://discord.com/developers/applications) → 애플리케이션 → **General Information** 의 **Application ID** 로 바꿔서 접속하세요.

```
https://discord.com/oauth2/authorize?client_id=CLIENT_ID&permissions=117760&scope=bot+applications.commands
```

- 권한(합계 `117760`):

| 권한 | 비트값 | 쓰는 곳 |
| --- | --- | --- |
| 채널 보기 (View Channels) | 1024 | 모든 명령 |
| 메시지 보내기 (Send Messages) | 2048 | 예약 알림·일정 알림 전송 |
| 링크 첨부 (Embed Links) | 16384 | 임베드 응답(도움말·투표·랭킹·달력 등) |
| 파일 첨부 (Attach Files) | 32768 | `/달력` PNG 이미지, `/일정내보내기` .txt |
| 메시지 기록 보기 (Read Message History) | 65536 | 권장 (채널 메시지 맥락 확인) |

슬래시 명령의 직접 응답은 인터랙션 응답으로 가지만, 예약 알림·일정 알림처럼 봇이 채널에 **직접 보내는 메시지**에는 위 채널 권한이 필요합니다.

- 인텐트: **MESSAGE CONTENT** (특권 — 포털 **Bot → Privileged Gateway Intents** 에서 켜기), `voice_states` (기본 포함, `/팀나누기`).
  **SERVER MEMBERS** 는 필요 없습니다. (자세한 내용은 위 "필요한 인텐트" 참고)

### 시간 파서 API

```python
from time_parser import parse_time, parse_korean_time, TimeParseError

parse_time("내일 오후 3시", now)         # datetime (한국 시간, naive) / 실패 시 TimeParseError
parse_korean_time("내일 오후 3시", now)  # datetime / 실패 시 None (기존 호환)

from time_parser import is_recurring, parse_recurrence
is_recurring("매주 월수금 9시")             # True (parse_time 은 반복 표현을 계속 거부)
r = parse_recurrence("매주 월수금 9시")
r.kind, r.description                       # ("cron", "매주 월·수·금 오전 9시")
r.trigger_kwargs()                          # {"day_of_week": "mon,wed,fri", "hour": 9, "minute": 0, "second": 0}
parse_recurrence("2시간마다").trigger_kwargs()  # {"seconds": 7200} → IntervalTrigger
```

## 배포

### Docker

```bash
docker build -t alram .
docker run -d --name alram --env-file .env -p 8080:8080 alram
```

컨테이너는 `python bot.py`(Procfile의 `web` 프로세스와 같은 명령)를 실행합니다.
모든 DB 파일은 컨테이너 안 `/app/data` 에 저장됩니다(Dockerfile 의 `*_DB_PATH` 환경변수). 컨테이너를 지우거나 새 이미지로 바꿔도
유지하려면 볼륨을 연결하세요: `docker run ... -v alram-data:/app/data alram`
`PORT`를 바꾸면 `-p` 의 컨테이너 쪽 포트도 맞춰 주세요(예: `-e PORT=3000 -p 3000:3000`).

### 리눅스 서버(OCI 등)에서 systemd + 자동 업데이트

GitHub 브랜치에 새 커밋이 올라오면 1분 안에 자동으로 받아서 봇을 재시작합니다.
재시작 후 봇이 실행되지 않으면 이전 버전으로 자동으로 되돌리고, 그 커밋은 다음 커밋이 올라올 때까지 건너뜁니다.

```bash
cd ~/alram                       # 저장소 폴더 (.env 에 DISCORD_BOT_TOKEN)
sudo deploy/install.sh main      # 따라갈 브랜치 (기본 main)
```

- 봇 로그: `journalctl -u alram -f`, 업데이트 로그: `journalctl -u alram-update -f`
- 지금 바로 확인: `sudo systemctl start alram-update`
- 자동 업데이트 끄기: `sudo systemctl disable --now alram-update.timer`
- 서버에서 파일을 직접 고치면 업데이트가 중단됩니다(`git status` 로 확인).
- `alram.service` 는 `MemoryMax=500M` 으로 1GB 서버에서 봇이 메모리를 과하게 쓰면 봇만 재시작되게 합니다.
- 설치 전에 기존에 `screen`/`nohup` 등으로 켜 둔 봇은 꺼야 합니다(두 개가 동시에 응답함).

### Procfile 기반 호스팅 (Heroku 등)

[`Procfile`](Procfile)의 `web: python bot.py`가 그대로 쓰입니다. 플랫폼 설정에서 `DISCORD_BOT_TOKEN`을 지정하세요.
`PORT`는 플랫폼이 주입합니다.
